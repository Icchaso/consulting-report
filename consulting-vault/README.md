# コンサル業務記録ツール 使い方

会議の録音・チャット・メールなど「実際にやった仕事の記録」を1か所に集め、
議事録・提案書・月次レポートを自動で下書きするための仕組みです。

- 記録の入れ物: Obsidian（オブシディアン。Markdownファイルをノートとして見るアプリ）
- 下書きを作るAI: Claude Code（クロード・コード。フォルダの中のファイルを読み書きできるAI）
- 仕分け・集計: 数本の Python スクリプト（パイソンで書かれた小さな自動処理プログラム）

いちばん大事な約束: **記録に無いことは資料に書かれません。** 書けない所は「要確認」と残ります。
「要確認」は、AIが空欄を作り話で埋めなかった印です。埋めるときは元の記録を探してください。

---

## あなたがやるのは3つだけ

1. **会議が終わったら、録音の文字起こしを `00_inbox/` に置く**
2. **週に1回（金曜など）、Slack・LINE・メールのエクスポート（書き出したデータ）を `00_inbox/` に入れる**
3. **月初に、できあがった下書きをレビューして送る**

---

## 最初にやること: クライアントを追加する

1. `01_clients/` の中に、クライアント名のフォルダを作る（例: `01_clients/サンプル商事/`）
2. その中に `raw` という空のフォルダを作る
3. `02_templates/_profile.md` をコピーして、クライアントのフォルダに `_profile.md` として置く
4. `_profile.md` を開いて、先頭の `---` と `---` で挟まれた部分（frontmatter（フロントマター。ファイル先頭の設定欄））を書き換える
   - `client:` … フォルダ名と**まったく同じ**名前
   - `aliases:` … ファイル名に使う呼び名。`[サンプル商事, サンプル]` のように角かっこで1行に書く
   - `slack_channels:` / `email_domains:` / `line_names:` … 使うものだけ。使わないなら値を空にする（行は消さない）
   - `style:` … 資料の文体（例: `です・ます調。簡潔に。結論から。`）
   - `{{ }}` と書かれた所は全部書き換える
5. 設定欄の下に、目標KPI（ケーピーアイ。目標にする数字）や注意点を書く

`01_clients/サンプル商事/` と `01_clients/テスト工務店/` は架空の見本です。実際に使い始める前に削除してください。

---

## ファイル名の付け方

`00_inbox/` に置くファイルは、次の形の名前にします。

```
日付_種別_相手_件名.md
```

| 例 | 意味 |
|---|---|
| `2026-09-14_meeting_サンプル商事_月次定例.md` | 9/14 のサンプル商事との定例会議の文字起こし |
| `2026-09-12_slack_サンプル商事_在庫の相談.md` | 9/12 の Slack でのやり取り |
| `2026-09-10_mail_テスト工務店_見積の件.md` | 9/10 のメール |
| `2026-09-14_memo_サンプル商事.md` | 電話や思いつきの一行メモ（件名は省略できる） |

- **種別**は `meeting`（会議）/ `slack` / `line` / `mail`（メール）/ `doc`（作った資料）/ `memo`（メモ）のどれか
- **相手**は `_profile.md` の `client:` か `aliases:` に書いた名前と**一字一句同じ**にする。違うと仕分けされず inbox に残ります
- 拡張子は `.md` か `.txt`
- 電話・移動中の思いつきは一番記録から落ちやすく、一番価値があります。一行でいいので `memo` を残してください

## 毎月の流れ

ここからはターミナル（文字でパソコンに命令する画面。Mac なら「ターミナル」アプリ）を使います。
最初に、このフォルダ（vault（ボールト。記録をしまう保管庫フォルダ））に移動しておきます。

```
cd このフォルダの場所
```

**1. inbox の中身を仕分ける**（毎日、または週1回）
```
python3 03_scripts/inbox_sort.py --dry-run   ← まず「どこに仕分けるか」だけ確認
python3 03_scripts/inbox_sort.py             ← 実際に仕分ける
```
仕分けられたファイルは `01_clients/<クライアント名>/raw/` に入り、元のファイルは `00_inbox/_done/` に移ります。
仕分けできなかったものは `00_inbox/` に残ります。ファイル名を直して、もう一度実行してください。

**2. 月初に下書きを作る**
```
claude
```
で Claude Code を起動し、次のように打ちます。
```
/monthly            ← 前月分を作る
/monthly 2026-09    ← 月を指定して作る
```
各クライアントの `2026-09/` フォルダに、稼働ログ・議事録・提案書・Q&A・月次レポートができます。

**3. レビューする**（見るのは3点だけ）
- 抜き打ちで3か所、元の記録（`raw/`）と見比べて、書かれていることが本当に記録にあるか
- 「要確認」が残っていないか（残っていたら、AIに埋めさせず元の記録を探す）
- 稼働ログの合計時間が、自分の体感と大きくズレていないか（ズレていたら記録の入れ忘れ）

**4. 確定版を `sent/` に置いて送る**
- Word や PDF にした最終版を `2026-09/sent/` に置き、クライアントに送る
- `sent/` に入れたものは「送った事実」なので、あとから上書きしない

**5. 送付記録を残す**
```
python3 03_scripts/send_log.py --client サンプル商事 --month 2026-09 --to 佐藤様 --files 月次レポート.pdf
```
`sent/送付記録.md` に、いつ・誰に・何を送ったかが追記されます。

**6. 月末に5分だけ振り返る**
「今月やったのに記録が無いこと」を書き出し、来月の記録の取り方を見直します。

## 広告運用レポート（PowerPoint）を作る

1. 広告マネージャから CSV を書き出し、`01_clients/<クライアント名>/ads/<YYYY-MM>/` に置く
   - 必須: レベル＝広告、内訳＝日（期間の分割＝1日）で書き出したもの
   - 推奨: キャンペーン単位・内訳なしの期間合計（正しいリーチを出すため）
   - 任意: 年齢×性別 / 配置 / デバイス / 地域 の内訳を1ファイルずつ
   - 前月比を出すなら、前月分も `ads/<前月>/` に置く
2. 目標対比を出すなら、`_profile.md` の設定欄に `ad_kpi_targets: [cpa=4500, roas=1.5, ctr=1.0]` のように書く
3. Claude Code で次のように打つ
```
/ad-report サンプル商事 2026-09
```
4. `01_clients/<クライアント名>/2026-09/ads/` に PowerPoint ができる。開いて次の点を見る
   - 「所見：要確認」と出ているページ（記録や根拠が無く、AIが書かなかった所）
   - 所見の文章と、表・グラフの数字が合っているか（各ページのノート欄に数字の出どころがある）
   - 次月施策が、議事録・提案書に書いた内容どおりか

数字はすべてプログラムが CSV から計算しています。AI が書くのは所見の文章だけで、文中の数字もプログラムが差し込みます。

---

## やってはいけないこと

- `raw/` の中のファイルを直す・消す（元の記録なので、そのままにしておく）
- `sent/` の中のファイルを上書きする
- 「要確認」をそれらしい文章で埋める

---

## セキュリティの注意

- **このフォルダを iCloud Drive や Dropbox の中に置かない。** クライアントの機密情報が入るため、クラウド同期（ネット上に自動で複製される仕組み）を使いません
- バックアップは、暗号化した外付けディスクか社内のNAS（ナス。ネットワークにつなぐ保存装置）に取ります
- 文字起こしは自分のパソコンの中で行うのが基本です（音声をパソコンの外に出さない）
- APIキー（外部サービスを使うための合言葉）は `.env` というファイルに入れます。`.env` は Git の管理から外してあります
- Git（ギット。ファイルの変更履歴を残す仕組み）で共有しているのは**ツール本体と架空サンプルだけ**です。実際のクライアントの記録（`01_clients/` の新しいフォルダ・`00_inbox/`・`04_logs/`）は `.gitignore`（Git に含めないファイルの一覧）で自動的に除外され、GitHub には上がりません。コミット（その時点の状態を記録すること）の前に `git status` でクライアントのファイルが入っていないか確認してください
- クライアントとの契約上、業務記録を保管してよいか確認しておいてください
