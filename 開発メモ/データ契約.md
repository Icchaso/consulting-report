# データ契約（全スクリプト・コマンド・テンプレート共通の約束）

設計書: `../コンサル業務記録ツール_設計書/02_設計書_詳細版.md`
vault の場所: `../consulting-vault/`（以下、パスは vault ルートからの相対）

この契約を変えるときは、影響するファイル（inbox_sort.py / worklog.py / check_sources.py / テンプレート / コマンド）を同時に直すこと。

---

## 1. 実行環境
- Python は **標準ライブラリのみ**（pip install 不要）。**Python 3.9 で動くこと**（macOS 標準の /usr/bin/python3 が 3.9.6）
  - `from __future__ import annotations` を使う。`match` 文・`X | Y` 型の実行時評価・3.10以降のAPIは禁止
- スクリプトは vault ルートを自動判定する（`Path(__file__).resolve().parent.parent`）。`--vault <path>` で上書き可能にする（テスト用）
- **macOS のファイル名は NFD（濁点が分離）で返ることがある。** ファイル名・クライアント名を比較する前に必ず `unicodedata.normalize("NFC", s)` する
- 文字コードは UTF-8 固定。改行は LF

## 2. フォルダ構成
```
consulting-vault/
├── 00_inbox/                 入口。ここに置くだけ
│   ├── _done/YYYY-MM-DD/     振り分け済みの元ファイル（inbox_sort.py が移動）
│   └── _要確認/              raw と衝突したもの等
├── 01_clients/<クライアント名>/
│   ├── _profile.md           利用者が手で書く
│   ├── raw/                  振り分け済み生データ。編集禁止
│   └── YYYY-MM/              生成物（作り直し可）
│       ├── worklog.md
│       ├── minutes/  proposals/  qa/
│       ├── report.md
│       └── sent/             納品した事実。上書き禁止。送付記録.md
├── 02_templates/
├── 03_scripts/
├── 04_logs/
├── 99_samples/               動作確認用のダミーデータ
├── .claude/commands/         /monthly /daily-check
└── CLAUDE.md
```
クライアントのフォルダ名 = `_profile.md` の `client:` の値。

## 3. 入口のファイル名規則
`YYYY-MM-DD_<種別>_<相手>_<件名>.md`（`.txt` も可）
- 種別: `meeting` / `slack` / `line` / `mail` / `doc` / `memo`
- `<件名>` は省略可（`2026-09-14_memo_サンプル商事.md`）。件名にアンダースコアが入ってもよい（先頭から3回だけ分割する）
- `<相手>` はクライアントの `client:` か `aliases:` のどれかと**完全一致**（NFC正規化後）したときだけ振り分ける

## 4. `_profile.md` の frontmatter（利用者が書く）
YAMLの**簡易サブセット**だけを使う（PyYAML不要で読めるように）：
- `key: value` の1行形式
- リストはインライン `[a, b, c]` 形式のみ
- 値が空なら null 扱い
```yaml
---
client: サンプル商事
aliases: [サンプル商事, サンプル]
slack_channels: [sample-shoji]
email_domains: [sample-shoji.example]
line_names: [サンプル商事 佐藤]
contract: 月額顧問（月2回定例＋チャット相談）
monthly_fee: 
contact: 佐藤 様（営業部長）
style: です・ます調。簡潔に。結論から。
---
```
本文（frontmatter の下）に、目標KPI・注意点などを自由記述する。

## 5. raw ファイルの frontmatter（inbox_sort.py が付ける）
raw ファイル = 下記 frontmatter ＋ 元ファイルの本文そのまま（改変しない）。元に frontmatter があった場合もそのまま本文として残す。
```yaml
---
date: 2026-09-14
type: meeting
client: サンプル商事
title: 月次定例
source_file: 2026-09-14_meeting_サンプル商事_月次定例.md
imported_at: 2026-09-14T22:00:12
duration_min: 58
message_count: 
estimated_minutes: 58
estimate_basis: 文字起こしの最終タイムスタンプ 00:58:10
---
```
- `duration_min`: 会議のみ。文字起こしの行頭 or 括弧内のタイムスタンプ（`[00:58:10]` `(58:10)` `00:58:10` `[00:00:05.120 --> 00:00:09.000]` 等）の最大値。取れなければ空
- `message_count`: slack / line のみ
- `estimated_minutes`: 所要時間の**推定**。係数は `03_scripts/config.json` で変更可能
  - meeting: duration_min（取れなければ本文の文字数 ÷ 300 を切り上げ）
  - slack / line: message_count × 2分（最低10分）
  - mail: 10分 / doc: 30分 / memo: 5分
- `estimate_basis`: 推定の根拠を日本語で1行（例「メッセージ12件×2分」）

Slack エクスポート由来の raw のファイル名: `YYYY-MM-DD_slack_<クライアント名>_<チャンネル名>.md`（1チャンネル1日1ファイル）

## 6. 生成物の frontmatter（/monthly で Claude Code が書く）
```yaml
---
type: minutes            # worklog / minutes / proposal / qa / report
client: サンプル商事
date: 2026-09-14         # 対象日（report / worklog は YYYY-MM）
generated_at: 2026-10-01T09:00:00
sources:
  - raw/2026-09-14_meeting_サンプル商事_月次定例.md
---
```
- `sources:` のパスは**クライアントフォルダからの相対パス**（`raw/…` / `2026-09/minutes/…` / `2026-09/worklog.md`）
- ブロックリスト形式（`  - path`）で書く。check_sources.py はインライン形式 `[a, b]` も読めること
- 本文末尾に必ず以下のフッターを付ける:
  ```
  ---
  本資料は以下の記録から作成: [[ファイル名1]] / [[ファイル名2]]
  ```
  （Obsidian のリンク。拡張子なしのファイル名）
- 書けない項目は「要確認」、根拠のない効果試算は「要試算」と書く

## 7. 生成物のファイル名
- `YYYY-MM/worklog.md`
- `YYYY-MM/minutes/YYYY-MM-DD_<会議名>.md`
- `YYYY-MM/proposals/YYYY-MM-DD_<テーマ>.md`
- `YYYY-MM/qa/YYYY-MM-DD_<テーマ>.md`（相談1件1ファイル）
- `YYYY-MM/report.md`

## 8. ログ
- `04_logs/inbox_sort.jsonl` … 1行1イベント `{"ts","action":"moved|skipped|conflict|unsorted|error","src","dest","client","type","reason"}`
- `04_logs/runs.jsonl` … スクリプト実行ごとのサマリー1行 `{"ts","script","summary":{...}}`（inbox_sort / worklog / check_sources / send_log 共通）
